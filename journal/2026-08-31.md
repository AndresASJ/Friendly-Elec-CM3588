# 2026-08-31 — Jellyfin Music library added (points at the slskd download dir)

## Summary
Jellyfin had only two libraries, `Movies` and `Shows`. None of the Soulseek music
was reachable from Jellyfin at all, so ~88 GB of FLAC sitting in
`/mnt/drive1/Downloads/Soulseek` was invisible to every client. Added a third
library, `Music`, pointed straight at that download directory.

## Changes
Created the virtual folder by hand, matching the on-disk shape of the existing
`Movies`/`Shows` definitions under `/DATA/AppData/jellyfin/config/data/root/default/`:

```
Music/
├── music.collection      # empty marker — sets collection type
├── music.mblink          # contains: /mnt/drive1/Downloads/Soulseek
└── options.xml           # EnableRealtimeMonitor, MusicBrainz for artist + album
```

Owned `1000:devmon` to match the neighbouring libraries, then `docker restart jellyfin`.

No mount change was needed — the Jellyfin container already bind-mounts `/mnt` →
`/mnt` wholesale, so the path resolves inside the container as-is.

## Why point at the download dir instead of the pool
Deliberate, owner's call. The tidier option was to create
`/mnt/storage/media/music` in the mergerfs pool (matching how `movies` and `shows`
work), re-point Lidarr's root folder there, and let Lidarr move + rename into it.
That was declined for now in favour of getting music playable immediately with
zero data movement.

The trade-off to remember:

- Lidarr's root folder **is** the download directory (`/mnt/drive1/Downloads/Soulseek`,
  root folder #1 "Soulseek Music"), so it manages music in place — 11 artists,
  257 albums, 1705 track files.
- Only a handful of those are actually renamed into clean `Artist/Album` folders.
  The other ~140 of the 154 top-level entries are still raw slskd folder names
  (`[1959] Chet`, `1962 - The Italian Sessions (1962, RCA-Victor)`), so they will
  surface in Jellyfin as junk artists and albums alongside the clean ones.
- `/mnt/toshiba/media/music` (Lidarr root folder #2, "Toshiba Music") is empty.
- `drive1` is at **98%** (52 G free). Moving music into the pool would have relieved
  that; it still needs doing at some point.

## Pending
The library is defined but **not yet registered** — Jellyfin only resolves a new
virtual folder during a library scan, and a bare restart does not do it. Confirmed
still absent from `BaseItems` (only `Movies` and `Shows` are present as
`CollectionFolder`), and `LibraryMonitor` is watching only the two pool paths.

Run **Dashboard → Scheduled Tasks → Scan Media Library** to pick it up. The
`RefreshLibrary` task is on its default ~12h trigger (last ran `13:01 UTC`), so it
would otherwise land on its own overnight.

## Unrelated things noticed
- `[ERR] NetworkManager: Unable to parse bind override: "https://jellyfin.asj.media"` —
  a full URL is sitting in a bind-address field that wants a bare IP. Harmless
  (it falls through to binding all interfaces) but worth clearing.
- `Movies/options.xml` still lists the pre-pool `PathInfos`
  (`/mnt/drive1/movies`, `/mnt/drive3/movies`, `/mnt/drive4/movies`) while

# 2026-08-31 (2) — Jellyseerr still held pre-pool root folders; every request had been failing silently

## Symptom
"Hamilton 2025 isn't torrenting." Nothing was in the qBittorrent queue at all
(0 torrents), and Radarr's last grab was **2026-08-14** — 17 days of nothing.

## Root cause
The hardlinking migration (2026-08-18, `docs/16-hardlinking-migration-plan.md`)
re-pointed Sonarr/Radarr root folders into the mergerfs pool:

| App | Root folder now |
|---|---|
| Radarr | `/data/media/movies` |
| Sonarr | `/data/media/shows` |

**Jellyseerr was never updated.** It kept sending the old absolute paths, so every
add was rejected by the *arr with HTTP 400:

```
RootFolderExistsValidator: Root folder '/mnt/drive3/movies' does not exist
```

The request was then marked FAILED in Jellyseerr and nothing ever reached qBit.
Sonarr requests had a *second*, older break stacked on top: Jellyseerr's
`activeProfileId` was `4`, but Sonarr only has profile `7` (`WEB-1080p`) —
`QualityProfileExistsValidator: Quality Profile does not exist`. That one predates
the migration and had been silently failing TV requests back to **2026-05-05**.

Direct adds in Sonarr/Radarr were unaffected, which is why TV kept arriving
(Reacher, Ted Lasso, Dr House all landed after the migration) and masked the
problem — only the Jellyseerr path was broken.

## Two places store the root folder

This is the part worth remembering. Fixing the server settings alone was **not**
enough:

1. **`settings.json`** — `radarr[].activeDirectory` / `sonarr[].activeDirectory`,
   used for *new* requests.
2. **`media_request.rootFolder` / `.profileId`** in `db/db.sqlite3` — a per-request
   snapshot taken when the request was made. This **overrides** the server default
   on retry, so every pre-migration request kept failing with the old path even
   after `settings.json` was correct.

## Changes

`/mnt/drive1/appdata/jellyseerr/settings.json` (container stopped for the edit,
backup at `settings.json.bak-20260831-225539`):

```diff
  radarr[0]:
-   "activeDirectory": "/mnt/drive3/movies"
+   "activeDirectory": "/data/media/movies"
    "activeProfileId": 4          # HD-1080p — valid in Radarr, unchanged
  sonarr[0]:
-   "activeDirectory": "/mnt/drive2/shows"
+   "activeDirectory": "/data/media/shows"
-   "activeProfileId": 4, "activeProfileName": "HD-1080p"
+   "activeProfileId": 7, "activeProfileName": "WEB-1080p"
```

Then the historical overrides (backup at `db.sqlite3.bak-20260831-*`):

```sql
UPDATE media_request SET rootFolder='/data/media/movies' WHERE type='movie' AND rootFolder LIKE '/mnt/%';
UPDATE media_request SET rootFolder='/data/media/shows'  WHERE type='tv'    AND rootFolder LIKE '/mnt/%';
UPDATE media_request SET profileId=7 WHERE type='tv' AND profileId=4;
```

68 rows carried a stale `/mnt/...` path. All 9 failed requests were then retried
via `POST /api/v1/request/<id>/retry`.

## Result

Failed-request count `9 → 0`. Five torrents downloading within a minute:

```
downloading  Hamilton.2020.NORDiC.1080p.BluRay.REMUX.AVC.TrueHD.Atmos7.1-DTS
downloading  The.Light.Between.Oceans.2016.1080p.BluRay.Remux.AVC.DTS-HD.MA.7.1
downloading  Lanterns.S01E01 / S01E02 / S01E03  (1080p WEB-DL DDP5.1 Atmos)
```

Note Radarr matched Hamilton to the 2020 Disney+ proshot — correct; TMDB 556574
carries `year: 2025` from the theatrical re-release but `digitalRelease: 2020-07-03`.

## Verified healthy along the way (not the cause)

- Port forwarding correct — gluetun `forwarded_port` `46693` == qBit `listen_port`.

## Still open
- **No alerting on failed Jellyseerr requests.** This sat broken for 17 days
  (TV: ~4 months) with no signal. The MEDIA_FAILED notification fires but clearly
  isn't reaching anywhere anyone looks. Candidate for an n8n workflow polling
  `/api/v1/request?filter=failed`.
- **`sonarr[0].seriesType` is `daily`** in `settings.json` — almost certainly wrong
  as a default (should be `standard`); Jellyseerr appears to send `standard` anyway.
  Left alone, worth a look.
- **qBit had 0 torrents** — nothing seeding at all, which conflicts with the
  private-tracker seeding policy. Separate question, not investigated here.
- `/mnt/storage/data` is an empty stray directory from the migration; harmless.
