# 2026-08-31 — Jellyfin Music library added (points at the slskd download dir)

## Summary
Jellyfin had only two libraries, `Movies` and `Shows`. None of the Soulseek music
was reachable from Jellyfin at all, so ~88 GB of FLAC sitting in
`/mnt/drive1/Downloads/Soulseek` was invisible to every client. Added a third
library, `Music`, pointed straight at that download directory.

## Changes
Created the virtual folder by hand, matching the on-disk shape of the existing
`Movies`/`Shows` definitions under `/DATA/AppData/jellyfin/config/data/root/default/`:

```
Music/
├── music.collection      # empty marker — sets collection type
├── music.mblink          # contains: /mnt/drive1/Downloads/Soulseek
└── options.xml           # EnableRealtimeMonitor, MusicBrainz for artist + album
```

Owned `1000:devmon` to match the neighbouring libraries, then `docker restart jellyfin`.

No mount change was needed — the Jellyfin container already bind-mounts `/mnt` →
`/mnt` wholesale, so the path resolves inside the container as-is.

## Why point at the download dir instead of the pool
Deliberate, owner's call. The tidier option was to create
`/mnt/storage/media/music` in the mergerfs pool (matching how `movies` and `shows`
work), re-point Lidarr's root folder there, and let Lidarr move + rename into it.
That was declined for now in favour of getting music playable immediately with
zero data movement.

The trade-off to remember:

- Lidarr's root folder **is** the download directory (`/mnt/drive1/Downloads/Soulseek`,
  root folder #1 "Soulseek Music"), so it manages music in place — 11 artists,
  257 albums, 1705 track files.
- Only a handful of those are actually renamed into clean `Artist/Album` folders.
  The other ~140 of the 154 top-level entries are still raw slskd folder names
  (`[1959] Chet`, `1962 - The Italian Sessions (1962, RCA-Victor)`), so they will
  surface in Jellyfin as junk artists and albums alongside the clean ones.
- `/mnt/toshiba/media/music` (Lidarr root folder #2, "Toshiba Music") is empty.
- `drive1` is at **98%** (52 G free). Moving music into the pool would have relieved
  that; it still needs doing at some point.

## Pending
The library is defined but **not yet registered** — Jellyfin only resolves a new
virtual folder during a library scan, and a bare restart does not do it. Confirmed
still absent from `BaseItems` (only `Movies` and `Shows` are present as
`CollectionFolder`), and `LibraryMonitor` is watching only the two pool paths.

Run **Dashboard → Scheduled Tasks → Scan Media Library** to pick it up. The
`RefreshLibrary` task is on its default ~12h trigger (last ran `13:01 UTC`), so it
would otherwise land on its own overnight.

  (it falls through to binding all interfaces) but worth clearing.
- `Movies/options.xml` still lists the pre-pool `PathInfos`
  (`/mnt/drive1/movies`, `/mnt/drive3/movies`, `/mnt/drive4/movies`) while
  `movies.mblink` correctly points at `/mnt/storage/media/movies`. Stale leftover
  from the hardlinking migration; the mblink is what actually resolves.
